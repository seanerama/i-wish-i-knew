# Stage 3: Runner spine: iwik run, preview, submit with vault and egress guard

- **Type:** feature
- **Depends on:** 1, 2
- **Milestone:** 0.1 walking skeleton
- **Work-item:** https://github.com/seanerama/i-wish-i-knew/issues/3
- **Design refs:** ADR-0001, ADR-0006; `contracts/runner-pack.md`, `contracts/member-api.md`; `docs/walking-skeleton.md`

## Objectives

The member half of the spine, and the end-to-end proof. A local operator runs
one protocol against the stub, the raw evidence stays in the vault, and only the
sanitized signed `Run` reaches the service after an explicit preview. This
stage closes the walking-skeleton test in `docs/walking-skeleton.md`.

## What to build

**packages/runner** (`commander`, Node built-ins for crypto and HTTP; published name `i-wish-i-knew`, bin `iwik`)

- Home directory `IWIK_HOME` (default `~/.iwik`): `config.json` (service URL), `token` (0600), `key.ed25519` (0600, generated by `iwik init`), `policy.json`, `vault/`, `plans/`.
- `iwik init --service <url> --token-file <path>`: creates the home, generates the Ed25519 keypair, prints the public key for enrollment.
- `iwik policy show`: prints the effective policy; default policy is `allow_execution: false`, `allowed_targets: []`, `budget_per_plan_usd: 0`, `allow_disruptive: false`.
- `iwik run --protocol <ref> --target <url> [--planned N] [--context k=v ...]`: loads the pack from `packs/` (path from config, repo-relative in dev), verifies the pack and harness digests against the registry's `ProtocolVersion` fetched from `GET /v1/protocols/{ref}` (or a `--offline` local manifest), refuses if policy disallows execution or the target host is not in `allowed_targets`, spawns the harness per `runner-pack` with `IWIK_ALLOWED_HOSTS` set to the target host only, collects outputs, derives `accounting` from `attempts.jsonl`, maps exit codes to `execution_status`, assembles the `Run` with required context fields present (unknown as `origin = unknown`), writes `vault/<run_id>/{run.json,stdout,stderr,attempts.jsonl,result.json}`, prints the `run_id`.
- `iwik preview <run_id>`: strips vault-only fields, sets `target.label_digest`, signs the JCS body, calls `POST /v1/contributions/preview`, stores `preview_id` alongside the run, prints the sanitization report and exactly what will be sent.
- `iwik submit <run_id>`: refuses without a stored preview; posts to `POST /v1/runs`; stores the receipt in the vault; idempotent on rerun.
- `iwik receipt <id>`: fetches and prints.
- Egress guard: the harness is spawned with `NODE_OPTIONS=--require <guard.js>` that monkey-patches `http`/`https`/`fetch`/`net.connect` to reject hosts outside `IWIK_ALLOWED_HOSTS`. This is a best-effort guard for Node harnesses in v1, and is documented as such.
- Every command exits nonzero with a one-line reason on policy denial; never prints token or key material.

## Interface contracts

- **Exposes:** the `iwik` CLI and `@iwik/runner` programmatic API (`run`, `preview`, `submit`) used by tests and by stage 5's MCP adapter.
- **Consumes:** `runner-pack` v1 (pack layout, env vars, exit codes), `member-api` v1 (`/v1/protocols`, preview, runs, receipts), `@iwik/contracts`.

## Testing requirements

- Move/extend the spine test so it is the full end-to-end from `docs/walking-skeleton.md`: stub server → programmatic `run` (planned 20, seeded 10 % errors) → assert vault contents and accounting → `preview` → `submit` `201` → resubmit `200` → tamper `409` → secret injection `422`.
- Policy tests: execution denied by default; target not in allowlist denied; both produce no harness spawn.
- Digest test: modify one byte in `harness/index.js` → `iwik run` refuses with `harness_digest_mismatch`.
- Egress test: harness attempting a second host is blocked and the run is `excluded` with reason.
- Vault permission test: files created `0600`, directory `0700`.
